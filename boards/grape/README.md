# 🍇 NextMicon Grape 🍇

Mid-range FPGA board for multi-channel phased-array acoustic field generation.

## Repository layout

- [`board`](board/): KiCad design and fabrication outputs
- [`breakout`](breakout/): breakout and test-fixture designs
- [`firmware`](firmware/): FPGA HDL and constraints

## Target specs

- FPGA: AMD Spartan-7 `XC7S50-1CSGA324C`
  - 52,160 logic cells
  - 120 DSP48E1 slices
  - 2,764,800 bits of Block RAM
  - 210 user I/O pins in the CSGA324 package
- GPIO: 128 pins reserved for phased-array channel outputs
- GPIO logic level: 3.3 V
- Channel count: 128 channels with one GPIO per channel
- Clock: 100 MHz onboard oscillator; USB 48 MHz and application clocks generated by MMCM/PLL
- Configuration: 128-Mbit QSPI flash
- USB: USB-C for power and control
- Power: USB 5 V input with FPGA core, auxiliary, and I/O rails
- Recovery: external JTAG and `PROGRAM_B`
- FPGA package: CSGA324, 15 mm x 15 mm, 0.8 mm ball pitch
- GPIO connectors: four 2x24, 2.54 mm headers using the Cherry 8-pin group geometry
- Placement study: 140 mm x 70 mm, four layers, deliberately unrouted
- Final regulator sizing: pending electrical implementation verification

The 128 GPIO signals are logic-level timing outputs. External level shifters,
gate drivers, and power stages must be used to drive acoustic transducers; the
transducers must not be driven directly from FPGA pins.

## Intended architecture

Grape receives phase and optional amplitude parameters from a host and produces
phase-synchronous waveforms for up to 128 acoustic channels. The baseline
firmware uses a common phase accumulator and per-channel phase offsets stored in
Block RAM. All channel parameters are double-buffered so that an update can be
applied to every output on the same clock boundary.

The baseline design targets externally calculated phase values. Coordinate-to-
phase calculation, multi-focus synthesis, and closed-loop field control are
reserved for higher-end boards such as Melon.

## I/O allocation

The CSGA324 package provides up to 210 user I/O pins. The checked allocation is:

| Function                        |      Pins | Notes                                    |
| ------------------------------- | --------: | ---------------------------------------- |
| Phased-array outputs            |       128 | Banks 15, 34 and 35; 3.3 V               |
| Clock and USB                   |         3 | Bank 14; 100 MHz plus USB D+/D-           |
| User strap, button and LEDs     |         4 | Bank 14                                   |
| Configuration and JTAG         | Dedicated | Bank 0 and Bank 14 configuration pins     |

The generated and machine-checked mapping is [`board/pinout.csv`](board/pinout.csv).
Each set of 32 GPIOs uses one 2x24 header. As on Cherry, every group of eight is
a contiguous 2x4 window with four inner-row and four outer-row signals; group
separators carry GND on the inner row and 3.3 V on the outer row. The mapping
is generated from AMD's official `xc7s50csga324pkg.csv` by
[`board/tools/generate_pinout.py`](board/tools/generate_pinout.py).

If complementary high-side/low-side signals are generated directly by the
FPGA, 128 GPIOs provide 64 channels. The preferred 128-channel implementation
uses one FPGA output per channel and generates complementary drive signals in
the external driver stage.

## Current hardware status

The existing KiCad files under [`board/src`](board/src) describe the earlier
Artix-7 `XC7A35T-1FTG256C`, 56-GPIO prototype. They do not yet implement this
Spartan-7 target specification. The schematic, PCB, power tree, FPGA symbol,
pin assignments, decoupling, and constraints must be migrated to
`XC7S50-1CSGA324C` before fabrication.

The replacement six-unit KiCad symbol
[`board/src/grape-fpga.kicad_sym`](board/src/grape-fpga.kicad_sym) is generated
from AMD's production `xc7s50csga324pkg.csv`; it contains all 324 unique package
balls and uses the matching `Package_BGA:Xilinx_CSGA324` footprint. Regenerate
it with [`board/tools/generate_fpga_symbol.py`](board/tools/generate_fpga_symbol.py).
The symbol and checked 128-GPIO pinout are ready; integration into the new
schematic and PCB is in progress. The old schematic and placement board remain
non-fabrication references until that migration is complete.

## Build

Grape is developed with a fully open-source FPGA toolchain. AMD Vivado is not
used or required by the intended build and programming workflow.

- HDL synthesis: [Yosys](https://github.com/YosysHQ/yosys)
- Place and route: [nextpnr-xilinx](https://github.com/gatecat/nextpnr-xilinx)
- 7-series device database and bitstream support:
  [Project X-Ray](https://github.com/f4pga/prjxray)
- Timing constraints: XDC
- Bitstream and QSPI programming:
  [openFPGALoader](https://github.com/trabucayre/openFPGALoader)

The repository will provide reproducible command-line build scripts and pinned
tool/database revisions. The exact `xc7s50csga324-1` part is present in the
Project X-Ray database; the complete build and programming flow must still be
validated on Grape hardware before release.

The final top-level port names, XDC pin constraints, clock constraints, and
bitstream/flash programming procedure will be documented after the schematic
and connector pinout are fixed.

## Before PCB fabrication

- Assign all 128 outputs using the official CSGA324 package pin file.
- Reserve configuration, JTAG, clock, USB/control, and debug pins first.
- Check every I/O bank voltage and the simultaneous-switching-output limits.
- Establish a worst-case power budget from AMD data-sheet values and measured
  activity from the open-source implementation.
- Verify regulator capacity, startup sequencing, thermal margin, and decoupling.
- Validate that the external driver input load is within the FPGA I/O limits.
- Add source-series termination where signal-integrity analysis requires it.
- Complete schematic ERC and routed-board DRC before generating fabrication data.
