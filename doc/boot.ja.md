# ブートシーケンス

[English](boot.md)

通信仕様：[CDCフラッシュ・プロトコル](flash.ja.md)

この文書はNextMicon Cherryのハードウェア、FPGAイメージ、ホストツールで共通となる
ブート動作を定義します。フラッシュ配置は、最終ビットストリームのサイズと`icemulti`での
確認が完了するまでは暫定です。

## イメージとコールドブート選択

W25Q32には、役割を固定した2個のFPGAイメージを格納します。

| `CBSEL0` | 役割   | 内容                               | フレーム・チャンネル |
| -------: | ------ | ---------------------------------- | -------------------- |
|      `0` | `boot` | 保護された書き込み・復旧用イメージ | BOOTとFLASH          |
|      `1` | `user` | ユーザーアプリケーション           | BOOTとUART           |

基板上のはんだジャンパーは `CBSEL0` です。オープンなら `boot` ブリッジすると `user` を選択します。ジャンパーの変更は次回の電源レール・リセット時に反映され、実行中のイメージには影響しません。`CBSEL1` はオプショナルでユーザイメージを増やせます。

## コールドブート

1. USB VBUSから給電します。`RESET`を離すと3.3 Vと1.2 Vのレギュレーターが有効になり、両電源レールが放電状態から立ち上がります。
2. iCE40のコンフィグレーション・コントローラーが、`0x000000`にあるコールドブート・アプレットとベクターテーブルを読み取ります。
3. `CBSEL[0:1]` をサンプリングしブートイメージを選択します。
4. 有効なコンフィグレーションのロード後、オープンドレインの `CDONE` がプルアップで High になります。
5. 選択されたイメージが 48 MHz の USB ロジックと D+ プルアップを有効にします。両イメージは同じ CDC ACM 識別情報とエンドポイント構成で列挙されます。

`boot` は橙色の `PROG` LEDを点灯し、ホストコマンドを無期限に待ちます。タイムアウトで `user` へ移行しません。`user` は `PROG` を消灯し、共通 BOOT マネージャーとフレーム化 UART バイトストリームを提供します。

## ブートに関係するUSBトランスポート

両イメージが 1 個の CDC ACM シリアル機能を公開します。EP1 IN は CDC 通知 EP2 OUT/IN はフレーム化バイトストリームです。

| チャンネル      | `boot`   | `user`   |
| --------------- | -------- | -------- |
| BOOT（`0x01`）  | 利用可   | 利用可   |
| FLASH（`0x02`） | 利用可   | 利用不可 |
| UART（`0x03`）  | 利用不可 | 利用可   |

GET_INFOが実行中の役割とcapabilityを返します。USB descriptor、VID/PID、Product、
Serial Numberは両イメージで同じです。

## ホスト要求によるウォームブート

両イメージがBOOTサービスを実装します。ウォームブートは`SB_WARMBOOT`の内部入力
`S1:S0`を使い、はんだジャンパーを再サンプリングしません。`S1`は常に`0`、`S0`は
`boot`（`0`）または`user`（`1`）を選択します。

1. ホストが対象を1バイト含むBOOT SELECT_IMAGEを送信します。`0`は`boot`、`1`は
   `user`です。
2. 実行中のイメージが役割と、`user`の場合はマニフェストを検証します。

   | ステータス | 意味                          |
   | ---------: | ----------------------------- |
   |        `0` | 要求を受理                    |
   |        `1` | イメージ値またはpayloadが不正 |
   |        `2` | userマニフェストが不正        |
   |        `3` | マネージャーがビジー          |

3. 受理時はUSBやQSPIを停止する前に、レスポンス・フレームとCDC IN転送を完了します。
4. 新しいQSPI処理を禁止し、実行中処理とWIPビットのクリアを待ち、通常の1ビットSPI
   コマンドモードへ戻して`/CS`をHighにします。
5. USBを切断し、`S1=0`のまま対象を`S0`へ登録した後、`SB_WARMBOOT`をアサートします。
6. 選択されたイメージがロードされ、同じUSB識別情報で再列挙されます。

実行中と同じ役割を選択した場合も再起動します。ウォームブートは物理ジャンパーを変更しないため、次回の`RESET`では再びジャンパー値を使います。

## 開発時の書き込み手順

1. ジャンパーをオープンにして`RESET`を押し、`boot`を起動します。
2. FLASHチャンネルで唯一の`user`領域を消去し、ビットストリームとマニフェストを書き込みます。
3. マニフェスト、CRC、フラッシュreadbackを検証します。
4. SELECT_IMAGE `1`を送信し、受理後に`user`の再列挙を待ちます。
5. 再度書き込む場合はSELECT_IMAGE `0`を送り、`boot`の再列挙を待ちます。

USBから書き込めるFPGAイメージは`user`だけなので、ホストツールで書き込み先を指定する
必要はありません。

## フラッシュ配置

4 MiBのW25Q32を、2個の256 KiBイメージ領域と3.5 MiBのユーザーデータ領域に分割します。

| フラッシュ範囲      |  サイズ | 内容                                       | 書き込み方針                   |
| ------------------- | ------: | ------------------------------------------ | ------------------------------ |
| `0x000000-0x03FFFF` | 256 KiB | コールドブート・テーブルと保護された`boot` | 工場／復旧ツールのみ           |
| `0x040000-0x07FFFF` | 256 KiB | `user`とマニフェスト                       | `boot`の書き込み機能のみ       |
| `0x080000-0x3FFFFF` | 3.5 MiB | ユーザーデータ                             | 明示的なユーザーデータ操作のみ |

工場出荷用イメージは 256 KiB 境界に揃えて作成します。

```bash
icemulti -c -a18 -o factory.bin boot.bin user.bin
```

通常のUSB書き込みで`boot`を消去または書き換えてはいけません。コールドブートには通常の
SPIコマンド・フレーミングが必要なため、ユーザーコードはW25Q32を永続QPIモードのままに
してはいけません。

## RESET、外部書き込み、復旧

`RESET`は電源レール・リセットであり、`CRESET_B`を直接操作するリセットではありません。
押している間は`PWR_EN`で両レギュレーターを無効にし、離すと電源レールを再起動して
ジャンパーをサンプリングします。3.3 Vレールの外部給電は通常動作としてサポートしません。

`CRESET_B`はプルアップされ、工場書き込みと復旧用にJ5へ接続されています。

1. USB から給電し 3.3 V 対応 SPI プログラマーを J5 へ接続します。
2. `CRESET_B` を Low にして共有コンフィグレーション・ピンをハイインピーダンスにします。
3. `CS/SCK/MOSI/MISO` で工場出荷用イメージ全体を書き込みます。
4. `CRESET_B` を解放し通常のジャンパー選択によるコールドブートを行います。

`user` が不正、またはSELECT_IMAGE `0` を処理できない場合は、ジャンパーをオープンにして `RESET` を押します。`boot` またはコールドブート・テーブルが破損した場合は外部 SPI で復旧します。

## ブート時のハードウェア制約

- コールドブート中は SPI ピンを外部から駆動してはいけません。
- コンフィグレーション後は実行中イメージが6本のQSPI信号を使用し、ウォームブート前に停止する必要があります。
- FPGAのE10ボールは48 MHz発振器で駆動されるため、HDLではクロック入力にします。
